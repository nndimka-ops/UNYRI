# Быстрая проверка переноса COCO на iOS — 9 сентября 2026

## Внесённые исправления

- AuthRepository объединяет параллельные refresh в одну задачу. Результаты refresh/login/register проверяют поколение сессии; logout отменяет старый refresh. Терминальное отклонение refresh очищает только свою сессию.
- AccountServices создаётся после входа и уничтожается при смене сессии. Репозитории профиля, чатов и сообщений больше не живут общими между аккаунтами. Signal container захватывает неизменный namespace вместо динамического чтения текущего пользователя во время незавершённой операции.
- База сообщений разделена по адресу сервера и пользователю. Старый общий messages.sqlite3 не удалён и не назначен произвольному пользователю: серверная история загрузится заново. Старые неотправленные записи автоматически не переносятся; файл сохранён для отдельной миграции с подтверждением владельца.
- Ошибка открытия SQLite больше не вызывает try!-crash: выводится экран ошибки с выходом из аккаунта.
- Поздние операции сообщений/ключей/чата/профиля проверяют поколение сессии перед использованием новых токенов. SignalKeyManager и SignalSessionManager привязаны к MainActor для сериализации синхронных операций с ключами.
- Кеш текущего чата показывается до сетевого запроса. Задержавшаяся загрузка истории другого чата не перезаписывает пагинацию текущего экрана.
- Открытый чат обновляется REST-запросом каждые 3 секунды только в активной сцене; задача отменяется при уходе с экрана/в фон. Это временный foreground catch-up, не полный WebSocket/global sync и не гарантия получения всех событий при больших разрывах истории.
- APIClient сохраняет отмену задач как CancellationError вместо обычной сетевой ошибки.
- Кеш presigned-URL аватара учитывает expiresAt с запасом 30 секунд.
- README обновлён: прежнее утверждение «только авторизация» уже не соответствовало коду.

## Состояние относительно Android

| Область | iOS сейчас |
|---|---|
| Вход, регистрация, восстановление сессии | Есть, исправлены гонки refresh |
| Профиль, био, поиск, показ аватара | Есть базовая реализация |
| Чаты и Signal-текст | Есть отправка, история, повтор неудачной отправки, SQLite |
| Онлайн-обновление | WebSocket realtime + reconnect (backoff 1с..30с) + `/sync` catch-up с durable курсором; 3с REST-polling остаётся только как foreground fast-path |
| Фото профиля с камерой/галереей/crop | Нет полного Android-потока upload → complete |
| Вложения, голосовые, реакции, редактирование/удаление | Нет полной реализации Android |
| Автоматическая очередь отправки и receipts | Есть durable outbox (transient=PENDING+backoff, permanent=FAILED, auth-terminal=logout), delivered + read receipts, `receipt.updated` WS |
| Аудио/видеозвонки | Требуются WebRTC, CallKit, сигналинг, разрешения, аудиосессия |
| Фоновые уведомления | Требуются APNs, а для соответствующих VoIP-событий PushKit/CallKit и поддержка на сервере |
| Локальный фоновый режим Android | Нельзя считать переносимым на iOS один-в-один; не добавлялись фиктивные background modes |
| Ручной адрес сервера и HTTPS | Адрес пока задаётся конфигурацией сборки; ATS содержит широкое dev-исключение, нужен отдельный этап |

## Проверка и пределы готовности

На Windows отсутствуют swift и xcodebuild, поэтому локальная компиляция Swift и установка на iPhone невозможны. Корректность доказывается через: (1) сборку в GitHub Actions (`ios-build.yml`, macos-latest, unsigned `.ipa` артефакт `COCO-iOS-unsigned`), (2) contract-тесты на чистом Swift (`Tests/CallContracts` + `Tests/RealtimeContracts`), компилируемые и исполняемые в CI без libsignal/UIKit. Это заменяет локальную проверку на Windows.

Следующий обязательный шаг на Mac/физическом устройстве: обмен Signal-текстом Android ↔ iOS, проверка receipts и offline-истории, затем два аккаунта A → logout → B, восстановление A. При обновлении старой установки отдельно проверить оставшийся общий SQLite-файл до его удаления или миграции.

Полного паритета с Android нет. Остались (по приоритету): вложения + полноценный редактор аватара, затем APNs/CallKit и звонки (WebRTC/сигналинг), затем reply/edit/delete/reactions, затем фоновые уведомления и настройки. Не начинать с имитации фона или временного отключения проверки TLS.
